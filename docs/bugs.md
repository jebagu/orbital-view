## Fixed Bugs

```text
2026-05-31: Hidden Lines could hide the Ground Plane grid in the native SceneKit review viewport. Root cause was that the invisible ribbed-sphere cutaway plane wrote to the shared depth buffer before ground-grid line nodes rendered, so the Hidden Lines clipping plane could reject ground-grid fragments even though Ground Plane has its own visibility control. Fixed by giving every SceneKit ground-grid line an explicit rendering order earlier than the ribbed-sphere cutaway plane while preserving the cutaway's rear-rib behavior. Regression coverage now asserts that with Ground Plane on, Ribbed Speaker Sphere on, and Hidden Lines off, grid line nodes render before the cutaway plane.

2026-05-31: Ribbed Speaker Sphere looked uniformly covered by fog instead of gaining useful depth. Root cause was the batch-wide ribbed material fog tint/dim pass: each of the two welded SceneKit rib batches received one fogged color/alpha sample, so Fog Density could blanket the whole sphere rather than showing per-rib depth. Fixed by removing fog from the ribbed material update key, clearing shader modifiers, keeping SceneKit global fog and cutaway-plane movement, and moving the canvas fallback fog veil behind the ribbed sphere while retaining per-segment color/fade behavior. True near/mid/far ribbed depth fog remains open.

2026-05-31: Sphere Palette and Ground Appearance did not have an explicit follow-main option, so a global Color Palette choice could be represented as copied local concrete palette values. Fixed by adding first-position `Same as Main Theme` choices for both trays, resolving follow-main at render time, keeping concrete local overrides independent after explicit selection, exporting follow-main flags with resolved palette compatibility fields, and inferring follow-main on older JSON when the saved local palette equals the main palette.

2026-05-31: Ground grid stroke width was fixed. Fixed by adding a review-only `Grid Thickness` slider with a `100%` default and `50%...250%` range, applying it to SceneKit grid cylinder radii and canvas fallback line widths, exporting/decoding the value, and including it in grid update keys and randomizer output without touching speakers, labels, source markers, Cube VU, or ribbed sphere topology.

2026-05-31: Horizontal Ribbed Speaker Sphere rings did not follow the selected color theme after vertical ribs started changing correctly. Root cause was that the vertical rib batch used the selected geodesic palette accent, but the horizontal ring batch still used `accentSecondary`; several themes keep that secondary role green/mint/pink, so horizontal rings appeared stuck while vertical ribs changed. Fixed by making both SceneKit rib batches and the canvas fallback use the selected geodesic accent hue, preserving lane separation through alpha/brightness rather than a different palette role. Regression coverage now asserts Rack Blue is blue-dominant for both vertical and horizontal rib materials.

2026-05-31: Ribbed Speaker Sphere rendered hot pink/magenta in live SceneKit pixels even after source-level material palette tests passed. Root cause was the rejected per-fragment ribbed fog SceneKit shader modifier path: SceneKit rendered the two batched ribbed materials with its shader fallback/error color, masking the retained Rack Blue diffuse/emission material state. Fixed by removing and clearing shader modifiers from the live ribbed-sphere material authority and keeping Geodesic Appearance palette/saturation on retained material diffuse/emission state. Regression coverage now includes a SceneKit snapshot pixel test that distinguishes Rack Blue from magenta, material names carrying the active geodesic style, and DEBUG-only overlay/probe coverage.

2026-05-31: Top-level color-theme clicks could appear not to affect the Ribbed Speaker Sphere after the shader fallback was removed. Root cause was control semantics: `Sonic Sphere Speaker Palette` changed speaker/app `renderStyle`, while the ribbed sphere listened to separate `geodesicRenderStyle`; additionally, the exported startup default kept `geodesicSaturation` at `0`, so direct geodesic palette changes could be hue-invisible unless the saturation slider was moved. Fixed by linking Sonic Sphere palette clicks into the geodesic palette until Geodesic Appearance is explicitly edited, and by lifting zero saturation to a visible value when a palette is selected. Regression coverage now pins the default-saturation lift and uses it in the Rack Blue rendered-pixel test.

2026-05-31: Ribbed Speaker Sphere structure colors did not visibly follow the `Geodesic Appearance` palette. Root cause was that the horizontal/structure lane used the neutral `structure` line token, so the independent geodesic picker and saturation could appear ineffective. Fixed by driving the SceneKit and canvas ribbed-sphere lanes from the selected geodesic palette accent and secondary accent colors before applying geodesic saturation. Regression coverage now checks both batched SceneKit ribbed-sphere materials respond to palette and saturation changes without topology rebuilds.

2026-05-31: Batched Ribbed Speaker Sphere fog still read too flat after the batch-wide fog parity pass. Root cause was thought to be that the SceneKit ribbed sphere resolved color and brightness once per vertical/horizontal batch material, while speakers, source markers, and labels had more local depth response. Attempted fix was SceneKit geometry/surface shader modifiers on the two ribbed-sphere batch materials, but visible user acceptance rejected it because fog still did not appear to affect the sphere geometry. Regression coverage only proves shader plumbing and must not be treated as visual proof.

2026-05-31: Fog affected speakers and labels much more than the Ribbed Speaker Sphere geometry. Root cause was that speakers/labels used the new per-depth atmospheric ramp, but the SceneKit ribbed sphere still used two batched constant materials plus a center cutaway plane, so the sphere geometry did not pick up comparable fog contrast when Fog Density changed. A later attempted fix added a sphere-geometry fog alpha, batch-wide material tint/dim, and denser cutaway-plane advance; that material tint/dim portion was superseded on 2026-05-31 because it created a uniform full-sphere blanket rather than accepted depth fog. The remaining accepted part is the cutaway-plane movement under dense fog plus global SceneKit atmosphere; true ribbed-sphere depth fog remains open.

2026-05-31: Fog visual quality did not create a strong depth feeling in the native SceneKit review app. Root cause was that fog relied mostly on SceneKit global distance fog and small rear-alpha tweaks; the shared fallback path returned the original alpha from `foggedAlpha`, and speaker/source material update keys did not force an immediate refresh for fog-slider depth-material changes. Fixed by adding a nonlinear camera-depth atmospheric ramp that reduces rear alpha, VU emission, hidden-line/rib fade, speaker/source color contrast, and label opacity while preserving selected speaker readability. SceneKit fog start/end/exponent values were retuned, palette changes now refresh fog color, and fog material updates remain bucketed with the existing meter-display cadence during camera motion/active spin to preserve the Cube VU performance contract. Regression coverage now asserts the front/mid/rear fog ramp and fog material refresh semantics.

2026-05-31: Ribbed Speaker Sphere lines looked broken even after the two-node SceneKit batching pass. Root cause was that the two batch meshes were still built from many independent open tube fragments: the default geometry generated 1,152 diagnostic rib/ring segments and gave each segment its own unshared tube endpoints, while partially transparent constant materials and the hidden-line depth-only cutaway made those tiny seams read as hard gaps. Fixed by keeping the same diagnostic segment math but adding an internal curve model, sweeping welded tubes along full vertical ribs and horizontal rings, sharing adjacent cross-section rings, closing horizontal rings, capping vertical endpoints, and treating rib alpha as opaque material brightness/emission. Regression coverage now asserts the default curve topology, unchanged default/medium/max diagnostic segment counts, two SceneKit ribbed nodes, welded vertex counts with vertical caps and no duplicated horizontal seam ring, opaque depth-reading/writing rib materials, camera-only cutaway-only updates, active-frame ribbed path skips, and Hidden Lines cutaway behavior.

2026-05-31: Ribbed Speaker Sphere geometry could still break up at very thin thickness settings. Root cause was that the review UI still allowed Rib Thickness down to `25%`, below the visually stable floor for the welded SceneKit tube geometry. Fixed by making the current stable `70%` thickness the new minimum, clamping loaded legacy/theme values below that floor up to `70%`, and pinning the range/default behavior in review tests.

2026-05-30: Native SceneKit review-app mouse orbit controls had both accepted drag directions inverted after the canonical yaw/pitch camera rewrite. Root cause was that `OrbitalViewportOrbitState.applyingDrag(translation:)` still mapped horizontal and vertical screen-space translation with signs opposite the accepted DomeLab-style browser mockup: rightward drag increased yaw and downward drag reduced pitch. Fixed by reversing both signs while preserving horizontal-to-yaw and vertical-to-pitch responsibilities, projection basis, canonical Z-up speaker data, SceneKit coordinate bridging, spin behavior, selection, and hit testing. Regression coverage now asserts right/left drag affect only yaw in the corrected directions and up/down drag affect only pitch in the corrected directions.

2026-05-30: Active spin could freeze the native SceneKit review app after the ribbed-sphere crash fix. Root cause was a lock inversion: the main timer path held the coordinator SceneKit mutation lock while committing a SceneKit transaction, and the SceneKit render queue entered `renderer(_:updateAtTime:)` and waited on that same lock, preventing the transaction from completing. Fixed by making the render delegate active-frame path use a non-blocking mutation-lock attempt and skip the current active camera frame when the main thread is already mutating/committing SceneKit state. Regression coverage now holds the mutation lock from a background thread and asserts the active render frame returns without camera, ribbed topology, ribbed material, or segment writes.

2026-05-30: Active spin with the ribbed speaker sphere could crash the native SceneKit review app with `EXC_BAD_ACCESS` in `updateRibbedSphereCutawayUniforms`. Root cause was concurrent SceneKit mutation: the main SwiftUI/timer path and SceneKit render queue both entered the ribbed-sphere cutaway material path, writing `SCNMaterial` KVC uniforms and the coordinator's `ribbedSphereCutawayMaterialStates` dictionary while also recalculating fitted speaker geometry. Fixed by removing the obsolete material-uniform cutaway path, making the invisible depth-only cutaway plane the sole hidden-line cutaway mechanism, caching the ribbed sphere fit on topology rebuild, and serializing coordinator SceneKit mutations so active render frames update only camera/cutaway-plane state instead of entering ribbed material/topology work. Regression coverage now asserts the active render delegate path does not write ribbed materials, rebuild topology, visit ribbed segments, or use material shader/KVC cutaway uniforms.

2026-05-30: Isometric view and spin used a tilted camera basis instead of canonical Z-up yaw/pitch. Root cause was that the isometric angle was baked into `baseViewDirection`/`baseUp`, then yaw/spin rotated around that tilted isometric up vector, so active spin orbited the camera basis instead of spinning the globe around canonical `Z`. Fixed by recalculating review camera presets from canonical yaw/pitch, using true normalized `+X/+Y/+Z` for Isometric, preserving isometric elevation during spin, defaulting review/export state to the isometric preset, and resolving unadjusted legacy saved cameras to the current preset. Regression coverage now asserts true isometric direction, orthonormal preset bases, Z-elevation-preserving spin, canonical +X projection, active-spin cadence, and unadjusted saved-theme migration.

2026-05-30: Hidden Lines did not consistently apply to the ribbed sphere frame, rear speakers, and rear speaker labels after the SceneKit ribbed batching pass. Root cause was that the batched ribbed sphere no longer had per-segment front/rear visibility, while speaker labels still used a separate front-half-only rule; the first material cutaway also used a single SceneKit Z plane, then a fragment discard path that hid the full ribbed frame in the headed app. Fixed by sharing the Hidden Lines depth visibility rule for speaker labels in SceneKit and canvas fallback, keeping selected labels visible, and adding an invisible depth-only SceneKit clipping plane that bisects the fitted ribbed sphere perpendicular to the current camera direction. `Hidden Lines` off now hides the rear half of the ribbed sphere; `Hidden Lines` on hides the clipping plane and reveals the full frame without rebuilding thousands of segment nodes.

2026-05-30: Dense Ribbed Speaker Sphere caused avoidable SceneKit render/update cost. Root cause was the review app modeling the ribbed dome as one SceneKit cylinder node per generated rib/ring segment, with default density about 1,152 segments and max density about 8,192 segments. Fixed the source-level model by batching ribs into two SceneKit mesh nodes, one for vertical ribs and one for horizontal rings, and by removing camera state from the ribbed material update key so camera-only motion no longer loops through segment visibility/material writes. Added benchmark flags for ribbed default/medium/max density and regression tests for segment counts, two-node batching, camera-only update skips, topology rebuilds, and batched material writes.

2026-05-27: The native SceneKit review app's left rail could clip the `Source` header and first source-selector segment at the physical window edge after adding the top-left Telemetry / Local Song / Impulse Test selector. Root cause was that the hidden-titlebar review window kept the left rail tight to the window edge while the new three-segment selector needed more horizontal room than the old local-song block. Fixed by widening the review rail and adding an explicit left window-edge inset before rail controls render. Regression coverage now asserts the wider rail and edge inset constants.

2026-05-27: The refreshed app could reopen on `Impulse Test` even though the new review default source is `Telemetry`, because the default saved theme was older JSON without `sourceMode` and its legacy impulse `driveMode` was used as the source fallback during startup. Fixed by tracking whether `sourceMode` was explicit in decoded settings and preferring the review default only for missing-source default-theme startup, while preserving legacy inference for explicit old-theme loads. Regression coverage now asserts both paths.

2026-05-25: The native SceneKit review viewport projected the canonical left/right axis backward after the Z-up conversion, and the visible SceneKit drag callback still used the old horizontal yaw sign. Fixed by computing the review projection horizontal basis from view direction cross up after pitch is applied and routing native/fallback drag handling through the corrected orbit-state helper, leaving speaker data, the Z-up contract, and the SceneKit coordinate bridge unchanged. Regression coverage now asserts canonical `+X` projects to screen right and `-X` projects to screen left for all review camera presets, plus rightward and leftward drags move yaw in the expected directions.

2026-05-22: Excite Comets and Impulse Test Orbiting Comets were too narrow and did not read clearly as moving VU trails. Fixed by replacing the old three-hotspot pattern with exactly two larger comets with broader heads and longer hot tails, shared by both the impulse source and audio-excited comet mode. Regression coverage now asserts two broad hot trails, multiple active speakers, and mono-envelope excitation.

2026-05-22: Speaker Height was visible in the Speaker Shape tray even though it no longer provided a useful review-app control. Fixed by removing the control, normalizing old saved `speakerHeight` values to the current flat cube geometry path, and excluding height from review-app geometry/material update keys.

2026-05-22: In the SceneKit review app's Meter Source tray, choosing Music could appear to leave the active source on the impulse mode. Fixed by simplifying the source setter, expanding explicit source states, and verifying in the relaunched app that the Active Meter row and footer switch to Music source after clicking Music. Regression coverage now asserts the updated source inventory and deterministic impulse variants.

2026-05-22: Jost speaker labels sometimes rendered 6/9 as dot-like glyph fragments in SceneKit. Root cause was the Jost digit outlines being brittle in the `SCNText` geometry path; switching from the variable TTF to the static `Jost-Regular.ttf` resource was necessary but not sufficient. Fixed by keeping `Jost-Regular.ttf` and rendering Jost speaker labels as AppKit-generated text textures on billboard planes, bypassing SceneKit glyph tessellation for that font. Regression coverage now asserts the Jost font resource, numeric label strings for channels containing 6 and 9, and the texture-backed label path.

2026-05-22: Minecraft speaker-label zeroes rendered like colon glyphs after the bundled Minecraft font started loading correctly. Root cause was the font's digit-zero glyph rendering poorly in the SceneKit label path. Fixed by using a Minecraft-only display-text fallback that substitutes `O` for `0` in speaker labels while preserving channel identity and leaving all other label fonts numeric.

2026-05-22: Speaker Labels font selector changed the selected setting but on-screen labels stayed in the system font. Root cause was SwiftPM flattening processed font resources into the resource bundle root while the CoreText font registry only searched a Fonts subdirectory, so all non-system font selections fell back silently. Fixed by resolving font resources from either the Fonts subdirectory or the bundle root and adding a regression test that verifies the actual NSFont PostScript names for Press Start 2P, Minecraft, and Chintzy CPU BRK.

2026-05-21: Cube VU speakers in the SceneKit review app appeared as solid purple cubes and showed an unintended cubical halo. Fixed by removing the separate halo SCNBox child nodes and driving the actual six SCNBox cube faces with a retained 9x9 pixelated face texture cache, while preserving material-only meter updates and avoiding overlay face planes.
```
